# Задача: сверстать сайт SECRETS Lounge

Ты работаешь в папке проекта `Secrets`. Всё, что нужно, уже лежит здесь. Работай самостоятельно, без вопросов на каждом шаге, и показывай прогресс через коммиты в GitHub.

## 1. Сначала прочитай (обязательно, целиком)

1. `03-tz/TZ-secrets-website.md` — техническое задание, структура блоков, анимации, этапы (§9).
2. `02-design/design-system.md` — палитра, типографика, сетка, ритм, запреты.
3. `02-design/tokens.css` — готовые CSS-переменные, копируешь в проект как есть.
4. `01-content/site-content.md` — весь текст сайта. Тексты переносить дословно, правки только из ТЗ §6.
5. `01-content/links-and-media.md` — ссылки и медиа.
6. `Referens/` (`13.jpg`, `8.jpg`) — посмотри картинки, это ориентир по композиции и приёмам.

## 2. Скиллы (обязательно, оба)

- **impeccable**: `/impeccable audit` после каждого блока, `/impeccable polish` и `/impeccable typeset` при доводке, в конце `/impeccable document` → `DESIGN.md`. Slop-детектор должен работать до каждого коммита.
- **taste-skill**: brief inference перед генерацией, audit-first, pre-flight перед выдачей каждого блока.

Если скилл не найден, остановись и скажи об этом, не подменяй его своими правилами.

## 3. Жёсткие правила цвета

Акцент оранжевый, второй цвет тёмно-зелёный, фон чёрный и бетонно-серый. **Бордовый, малиновый и красный запрещены.** Любой цвет берётся только из `tokens.css`, значений hex в компонентах быть не должно.

## 4. Ресурсы

Скачанные материалы лежат в `assets/`:

- `assets/menu-scans/scan-01..20.jpg` — сканы меню (закуски, вина, виски, кальянная карта). Не фото зала.
- `assets/venue/` — настоящие фото зала, кухни, бара и кальянов, снятые с CDN старого сайта. Оптимизированные версии — в `public/img/venue`, `public/img/food`, `public/img/bar`, `public/img/hookah`.
- `assets/brand/` — `logo.png`, `icon.svg`, `og.jpg`.
- `assets/menu-pdf/menu-1..5.pdf` — меню. **`menu-2.pdf` повреждён** (это HTML), не используй его.
- `assets/html/` — HTML старого сайта, для сверки текста.

Не подключай файлы из `assets/` напрямую. Скриптом (например, `sharp`) сделай оптимизированные AVIF + WebP в нескольких размерах в `public/img/`, исходники оставь нетронутыми.

## 5. Стек и порядок

Стек из ТЗ §1: Vite + TypeScript, нативный CSS с `@layer`, GSAP + ScrollTrigger + SplitText, Lenis. Структура репозитория из ТЗ §8.

Порядок работ строго по ТЗ §9 (этапы 1–12). Не перескакивай: сначала каркас и типографика, потом блоки сверху вниз.

## 6. Git и публикация (главное для меня)

Я наблюдаю за работой через GitHub, поэтому:

- Репозиторий: `https://github.com/stasjuicytrax-arch/Secrets.git`, ветка `main`, remote `origin` уже настроен.
- **Пушь после каждой итерации правок и после каждого этапа**: закончил этап ТЗ, блок страницы или любую правку по моему замечанию — сразу `git add`, `git commit`, `git push origin main`. Даже мелкая правка (цвет, отступ, текст, скорость анимации) — это отдельный коммит и отдельный пуш. Не копи изменения: между пушами не больше 10–15 минут работы, а после моей правки пуш идёт сразу, как она готова.
- Это нужно, чтобы я смотрел результат на GitHub и согласовывал правки с заказчиком по свежей версии. Поэтому в каждом коммите сайт должен собираться (`npm run build` без ошибок), иначе публикация по ссылке сломается. Перед пушем прогоняй сборку.
- Сообщения коммитов на английском в формате `feat: hero section with amber glow`, `fix: ...`, `style: ...`, `chore: ...`. Одна мысль на коммит.
- Перед пушем: `git pull --rebase origin main`. Никогда не используй `--force` и `-f`.
- Не коммить `node_modules`, `dist`, `.env`, токены, ключи и любые секреты.
- На этапе 1 сразу добавь GitHub Actions workflow, который собирает сайт и публикует его на GitHub Pages (`base: '/Secrets/'` в `vite.config.ts`), чтобы результат можно было открыть по ссылке. Напиши мне одной строкой, что нужно включить в настройках репозитория (Settings → Pages → Source: GitHub Actions).
- Локально держи запущенным `npm run dev`.

## 7. Как отчитываться

После каждого пуша одна строка в терминал: что сделано, номер этапа, ссылка на коммит. Без длинных пересказов.

Когда я присылаю замечание или правку: вноси её, коммить, пушь и пиши одну строку «что изменил + ссылка на коммит». Не переделывай соседние блоки без моей просьбы.

Останавливайся и спрашивай только в трёх случаях: ошибка авторизации на GitHub, отсутствует нужный файл или скилл, выбор, который нельзя откатить.

## 8. Определение готовности блока

Блок считается готовым, когда:

1. Верстка совпадает с ТЗ и дизайн-системой (палитра, типографика, отступы, ритм).
2. Анимации из ТЗ работают, а при `prefers-reduced-motion: reduce` отключены.
3. Адаптив проверен на ширинах 375, 768, 1280 и 1920.
4. `/impeccable audit` не показывает замечаний уровня slop.
5. Изменения запушены в `main`.

Начни с этапа 1.
